# Publication correction, 2026-10-01

This post-result correction supersedes conflicting production-ranking and memory-stop prose in the September 30 amendment and fix report, and the October 1 ranking amendment. The frozen preregistration body and archived hash are unchanged. No independently timestamped freeze is established by these repairs. Implementation evidence is [ranking code](https://github.com/transitxlabs/transit-access-audit/blob/main/src/transit_audit/routing/bounds.py) and [evaluation code](https://github.com/transitxlabs/transit-access-audit/blob/main/scripts/run_bounds_evaluation.py); local verification is in [the phase 5 report](../milestones/PUBLICATION_FIX_REPORT_P5_2026-10-01.md).

Production verification uses exact accessible/inaccessible counterfactuals for a time-selected subset. Rankings compare only evaluated fields. Skipped impact is unknown, including fields not started before the soft candidate-start budget. A running candidate can exceed its budget. Calgary and Edmonton use 600 s and 1,800 s respectively; TTC ranking is not run. Fixture enumeration may be exhaustive without making production exhaustive. These are implementation choices, not a global-top guarantee or expected verification value. [Ranking implementation](https://github.com/transitxlabs/transit-access-audit/blob/main/src/transit_audit/routing/bounds.py).

Memory checks run continuously during reading, routing, ranking, sensitivities, validation and plotting. Descendant discovery traverses every generation; failed discovery and incomplete measurements yield null. Complete `top MEM` and resident-set (`rss`) observations retain separate types and separate sampled maxima. An observed excess propagates as an evaluation failure. Samples are not atomic and can miss transient peaks; interruption of a native call may be delayed. Unavailable observations explicitly record that the stop could not be enforced. Neither the 12,288 MB threshold nor a sampled maximum is a certified hard cap or certified peak. [Memory monitor implementation](https://github.com/transitxlabs/transit-access-audit/blob/main/scripts/memory_monitor.py), [Python threading](https://docs.python.org/3/library/threading.html), [Python subprocess](https://docs.python.org/3/library/subprocess.html), [Linux resident-memory definition](https://man7.org/linux/man-pages/man1/ps.1.html).

Java heap allocation reserves the larger of observed parent memory and 2,048 MB, plus the larger of 1,024 MB and 25 percent of the total budget for native JVM memory. These reserves are conservative allocations, not measured overhead guarantees. Insufficient remaining heap budget fails. The live tree monitor remains necessary: `-Xmx` limits heap, not total JVM memory. [Validator bridge](https://github.com/transitxlabs/transit-access-audit/blob/main/src/transit_audit/validator/mobilitydata.py), [Java launcher documentation](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html).

The previous reported 388.9 s run and unavailable/zero RSS observation in the September 30 report are historical. Use current generated timing and memory availability, not that record as a resource guarantee. This correction does not retrospectively turn missing memory measurements into observed peaks.
